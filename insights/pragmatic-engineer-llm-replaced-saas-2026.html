我用LLM在20分钟内替换了一个$120/年的微SaaS

来源：The Pragmatic Engineer (Gergely Orosz) · 2026-03-30 · ⭐ 4/5

发生了什么

Gergely在网站上用Shoutout.io（$120/年）显示用户好评。用了4年后，billing系统坏了3年没修，客服回复的链接也是坏的。于是他决定用Codex重建。

重建过程：
1. 让Codex制定计划（移除第三方依赖，在代码库中存储好评）
2. 微调计划（采用模块化方案，好评存JSON文件，编译时生成HTML）
3. 添加构建步骤（本地 + Netlify构建触发）
4. 测试 → 调UX → 部署
总耗时：20分钟

对软件工程师意味着什么

  • 开发者比普通用户更容易"移植"：需要人类判断UI布局和技术选型，Codex一开始用flexbox模型做错了
  • 好玩且有价值：不只是省$120，而是真正了解了AI工具的能力边界
  • 需要验证LLM输出：非开发者也能做，但会更慢更费劲

对SaaS行业的冲击

  • 静态SaaS最脆弱：不提供持续价值（如合规、实时分析、平台连接）的工具最容易被替换
  • 维护不能停：Shoutout 4年不修billing → 用户流失。3年不修 → Gergely离开
  • 微SaaS的买卖逻辑变了：Shoutout被转手两次，新买家期待零维护收益。但当产品体验下降，用户会立即用AI重建
"到了客服给我发来可用链接的时候（2小时后），我已经完成了迁移。"
核心洞察："Broken window"不再被容忍。AI让技术债务和用户体验下滑的代价从"令人讨厌"变成"可以被立即替换"。SaaS的护城河从"功能"转向"持续价值"和"用户粘性"。

文章价值

★★★★☆ — 非常具体的亲身经历，不是泛泛的"AI会取代SaaS"论调，而是精确描述了边界条件：什么SaaS容易被替换，什么SaaS仍然安全。对产品策略和技术决策都有参考价值。
