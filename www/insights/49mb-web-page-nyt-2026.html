📄 The 49MB Web Page

⭐⭐⭐⭐⭐ 5/5
新闻网站的性能噩梦 | Last updated: March 16, 2026
来源: thatshubham.com/blog/news-audit
标签: Web Performance Ad-Tech Privacy UX

📋 概述

作者为了"看四个标题"访问了纽约时报网站，结果遭遇了：422 个网络请求、49 MB 数据传输、页面加载用了两分钟才稳定下来。这篇文章深入分析了现代新闻网站的性能问题、追踪器泛滥和敌对用户体验设计。

📊 触目惊心的数字

422 请求 49 MB 2 分钟 ≈ Windows 95 大小 ≈ 10-12 首 MP3

🔍 发生了什么

1. 用户请求文本

用户只是想看新闻标题，但浏览器被迫下载 5MB 的追踪 JavaScript。

2. 静默的拍卖

浏览器在后台运行程序化广告拍卖，向 Rubicon Project、Amazon Ad Systems 等交易所发送数十个并发出价请求。这些请求是异步的，但它们的有效载荷对浏览器主线程极其不友好。

3. 获胜者注入

出价获胜者会注入一个用户完全没要求的弹窗广告。

🔐 隐私噩梦

  • 行为追踪：持续的心跳监控，用户的一举一动都被追踪
  • POST 信标：发送到 a.et.nytimes.com/track 的追踪请求
  • 隐形像素：背景中的隐形像素重定向到 doubleclick.net 和 casalemedia
  • 跨站身份拼接：帮助广告网络在不同网站之间建立用户的跨站身份
  • 讽刺的是：追踪初始化伴随着 purr.nytimes.com/tcf（欧洲 IAB 透明度和同意框架）请求。"purr"（猫在翻口袋时发出的声音）—— 太讽刺了！

💰 敌对架构的经济学

Publishers aren't evil but desperate

出版商被困在程序化广告的死亡螺旋中，用长期读者留存换取短期的 CPM（千次展示费用）。

  • 可查看性（Viewability）和页面停留时间是最重要的指标
  • 每一个敌对的 UX 决策都源于这两个指标
  • 读者停留越久，出版商可以收取的 CPM 越高
  • 你的挫败感就是产品

🤔 结论

现代新闻 UX 存在一个悖论：你被迫点击的 cookie 同意横幅只是为了保护出版商的法律护盾，而他们却在后台愉快地挖掘你的数据。读者不被软件尊重。出版商被激励系统挟持，这种系统不仅鼓励黑暗模式，还奖励黑暗模式。
