什么是 pre.dev？

pre.dev 是一个完全自主的软件工程师，不是 copilot、不是自动补全、不是聊天机器人生成代码片段。它是一个真正的自主软件工程师，从想法到部署的生产级代码。

💡 核心能力：
你描述想要构建的东西 → agent 研究问题 → 生成完整架构和路线图（含里程碑和用户故事）→ 自主编写和发布代码。任务按任务、分支、PR 推进。每个任务在隔离沙箱中运行，进行类型检查、linting 和无头浏览器视觉验证。

关键洞察

  • 瓶颈不是代码生成，而是规划 — Andrej Karpathy 提到的从"vibe coding"到"agentic engineering"的转变
  • specs 就像编译器通道 — 不直接从想法到代码（有中间表示：详细架构包含节点、边、依赖和用户故事）
  • 多模型架构 — Claude, Gemini, GPT, MiniMax, Qwen, GLM 等，还针对自己的数据集微调模型
  • 隔离任务上下文系统 — 不把整个代码库放入一个上下文窗口（这是大多数 AI 工具在大项目上失败的原因）

技术栈

  • 前端： React 18 + Vite, Redux Toolkit, Radix UI + Tailwind
  • 后端： Node.js + Express + GraphQL (Apollo Server), Redis, WebSocket, Bun
  • 数据库： MongoDB Atlas
  • AI 层： 多模型 + 微调
  • Agent 基础设施： Kubernetes (GCP), Docker 隔离, Playwright 视觉验证, gRPC

三阶段增长

  1. 阶段一： 规划和 spec 引擎（架构部分）
  2. 阶段二： 自主编码 agent，大幅扩展价值主张
  3. 阶段三（当前）： 完全自主 agentic 工程师 — 规划、编码、验证、部署，全部自主

创始人的建议

  • 让人们付费 — 不是"我完全会付这个"，而是真正掏出信用卡
  • 选择一个尴尬地具体的小众市场
  • 几周内发货，不是几个月
  • 不要藏在产品工作背后 — 参加销售电话
  • 构建你真正使用的东西

未来展望

让 agent 处理越来越复杂、长时间运行的工程工作。当前可以自主工作数小时或数天，目标是数周。拥有整个产品生命周期的 agent — 规划、构建、基于用户反馈迭代、发布更新。
